The Memory page in the Corunner web app is the window into your organization's memory. It holds two content stores Corunner maintains for you: **Memory** (what is true) and **Learnings** (what has worked). Admins also get a **Review** audit trail and an **Insights** view of the quality of that memory.

Header copy in the app reads: _"What Corunner knows about your organization: durable facts and decisions (Memory), reusable solutions (Learnings), and the quality of its organizational understanding."_

## The four tabs

### Memory

Durable facts, decisions, owners, and context Corunner has captured. This is what agents draw on when they need to answer "who owns this?" or "what did we decide?" without asking the team every time.

### Learnings

Reusable solutions and approaches distilled by the Learning Engine. Where Memory captures **what is true**, Learnings capture **what worked**, so agents can apply the same pattern the next time a similar situation shows up.

### Review (admin-only)

The audit trail of the Learning Engine's decisions: what it captured, what it discarded, and why. Use it to keep the Learning Engine honest and to spot organizational patterns you want to correct at the policy level.

### Insights (admin-only)

A view of the quality of Corunner's organizational understanding: coverage, freshness, and confidence. Use it to see where memory is thin and which parts of the org Corunner needs more signal on.

## How memory is populated

Memory is captured passively from chat conversations and actively when someone says "remember this" to the [Memory/Curator Agent](/agents/roster). Learnings are distilled by the Learning Engine over time from the outcomes of agent actions.
