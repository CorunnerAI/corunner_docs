## How it works

1. You mention `@Corunner` or reply in a thread it is already part of.
2. Corunner reads the surrounding context from the thread and from the tools you have connected.
3. A specialist agent (PM, Engineering, Standup, Assistant, and more) picks up the request. You do not have to route by hand.
4. Reasoning streams back into the thread as a reply, with citations from your stack where relevant.
5. If the response includes an action that touches a production system, a customer, or a person, the message includes **Approve**, **Edit**, and **Reject** controls.

## What is unique in chat

- **One `@Corunner`, the right specialist every time.** You do not pick who to ask. The Assistant is the default fallback if no specialist fits.
- **Context is preserved.** Corunner remembers earlier conversations in the same team so it does not start from zero each time.
- **Human approval by default.** Approvals are acted on in chat, not in the web app. The `/approvals` page in the web app is a read-only history.
- **Multimodal inputs.** Screenshots, diagrams, whiteboards, and product mockups can be posted directly into a thread.

## What the web app is for

The web app exists for setup and administration. Day-to-day work stays in chat. See the [Workspace Administration](/admin/dashboard) section for what admins do outside chat.
